# インストールと最初の依頼

原文：{{src:docs/guide/01-setup.md}}、{{src:README.md}}。

Cursorのチャットで次を入力します。

```text
/add-plugin pstack
```

インストール後はモデル設定を行います。

```text
/setup-pstack
```

## setup-pstack {#skill-setup-pstack}

原文：{{src:skills/setup-pstack/SKILL.md}}。

このスキルは、役割ごとのモデルを `~/.cursor/rules/pstack-models.mdc` に保存します。利用可能なモデルを検出し、既存設定があれば読み込み、推論予算と役割別の割り当てを確認してから書き込みます。

予算の選択肢は `unlimited`、`large`、`medium`、`small` です。原文ではそれぞれ既定値維持、`xhigh`、`high`、`medium` に対応します。これは推論強度の設定であり、金額やトークン数の上限を保証する契約ではありません。

実在するモデル識別子は、検出済みの集合に含まれるものだけを保存します。希望する強度がない場合は同じ系列の利用可能な下位強度を探し、選べなければ利用者に確認します。名前を推測して書きません。

## 役割と継承

| 設定の種類 | 読み方 |
| --- | --- |
| `feature, refactoring` | 機能追加とリファクタリングの実装担当 |
| `hardest tasks` | 横断設計や難しい並行処理などの難題 |
| `judgment and prose` | 判断と文章 |
| `how explorer` / `how explainer` | コード探索と説明 |
| `why investigators` / `why synthesizer` | 根拠収集と統合 |
| `arena runners` / `architect runners` | 独立した候補を作るパネル |
| `interrogate reviewers` | 差分を別々に点検するレビュアー |
| `swarm workers` | 分担作業の既定モデル |

`auto` と `inherit-parent` はモデル名ではなく、親チャットのモデルを継承する別名です。どちらも子エージェントの `model` 指定を省きます。パネルの値はリストで、各要素が1人分です。別名の要素も人数に数えます。

設定のない役割はスキルの既定値を使います。ある役割を既定値に戻すなら、その行を削除します。設定をやり直すと、変更済みのモデル系列・リスト・別名は引き継がれます。原文は、0.15.3より前に作ったルールが旧既定値を固定している可能性も説明しています。

## 実行後にすること

ルールは新しいセッションに適用されます。設定後は新しいチャットを始めます。プロジェクトに実アプリを操作する検証スキルやハーネスがなければ、`create-verification-skill` の作成を一度提案します。断っても設定作業は完了します。

> **例（本書独自の例。原文にはありません）**
>
> `/poteto-mode CLIに --json を追加してください。従来のテキスト出力はバイト単位で維持し、両方の出力を確認してください。`

最初の依頼では、狭い変更と明確な検証条件を選びます。TODOの先頭に選ばれたプレイブックの手順が並ぶことを確認します。省略した手順も `skip: 理由` として残るため、実施内容を追えます。
