# teachとrecall：理解と作業文脈の復元

## teach {#skill-teach}

原文：{{src:skills/teach/SKILL.md}}。

`/teach` は、人が仕組みを理解するための説明を作ります。コードの変更は目的ではありません。`how` で現在の動作、`why` でその理由を調べ、相手の関心に合わせて一つの説明へまとめます。小さい変更なら片方で足りる場合もあります。

最初に短い定義を示し、利用者の操作と実際に起きることを結びつけます。複数の要素を図にする場合は、最初から全部載せず、前の図へ一要素ずつ加えて理解を積み上げます。説明のために言い換えても、`why` の確信度は変えません。推測を確定した理由に変えてしまわないためです。

> **例（本書独自の例。原文にはありません）**
>
> `/teach このPRの再試行処理を説明してください。利用者が再送ボタンを押してから何が起き、二重送信をどこで防ぐのかを知りたいです。`

## recall {#skill-recall}

原文：{{src:skills/recall/SKILL.md}}。

`/recall` は、複数の最近の会話と共有記録から、作業の現在地を復元します。既定は現在のワークスペースの過去7日間です。対象期間、話題、ワークスペースを固定してから探します。他プロジェクトの履歴を無断で広げて読みません。

本人の会話には目的と判断が残ります。一方、同じ機能に対する他者の不具合報告、取り消された修正、稼働中のエラーは共有記録にあります。機能やサブシステムが指定されていれば、`why` の調査手順も使って両方を調べます。

見つけたPRやブランチは、現在のGitやGitHubの状態と突き合わせます。出力は最大5項目の概況、作業ごとの状態、最大5項目の問題、最も役立つ次の一手です。`[merged #N]`、`[open PR #N]`、`[verified, uncommitted]` などを使い、未完了を完了に混ぜません。

## 選び分け

| 必要なこと | 選択 |
| --- | --- |
| 仕組みを理解したい | `teach` |
| 複数の会話をまたぐ最近の文脈を戻したい | `recall` |
| 特定の前のチャットを引き継ぎたい | `session-pickup` |
| 作業習慣から自分用スキルを作りたい | `automate-me` |

会話を一つ再開することと、最近の活動全体を復元することでは、読む範囲と成果物が異なります。すでに十分な引き継ぎ情報があれば、`recall` は履歴の再探索を省けます。
